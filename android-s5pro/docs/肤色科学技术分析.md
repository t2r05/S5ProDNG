## 一、Q1：S5 Pro 胶片模式清单、作用对象、RAF 记录

### 1.1 确切名称（菜单档位）

**A 已验证** —— dpreview 评测（Simon Joinson，2007-07-05，经 Wayback 存档读取）：

- 评测第 1 页：*"Three new variations of the original film simulation mode (F1) have been added (five modes in total)"*；前代 S3 Pro 仅 F1、F2 两档。
- 评测第 9 页拍摄菜单表：**Film Simulation = Standard（默认）· F1 · F1a · F1b · F1c · F2**，每档附 Fine Tune：Color / Tone / Sharpness 各 −2..+2。菜单另有独立的 Color（High..ORG / B/W）、Tone、Sharpness 项。
- 评测第 13 页按**说明书原文**逐条描述（*"According to the manual the Film Simulation modes are described as follows"*）：

| 模式 | 官方描述（评测转述手册） |
|------|--------------------------|
| **F1** | 抑制闪光拍摄时的高光溢出（flaring），强调皮肤色调的平滑过渡；面向影棚人像、"专业级负片" |
| **F1a** | 较 F1 饱和度略增强 |
| **F1b** | 皮肤色调平滑过渡，同时自然色（蓝天等）鲜艳；适合日光人像 |
| **F1c** | 较 F1 锐度提升；适合时装拍摄 |
| **F2** | 自然色鲜艳还原；适合风光/自然摄影（即所谓 **"Velvia 模式"**） |

- 评测第 13 页并注：选非 STD 胶片模拟时**不能**单独修改 Color/Tone/Sharpness 参数（第 9 页菜单的微调挂在 Film Simulation 菜单之下）；评测实拍认为 F1a/F1b/F1c 三档差异细微。

**命名辨误（A）**：任务原假设 "F-Standard / F1 F-Chrome / F2 F-Pro" 与证据不符。S5 Pro 官方菜单即 Standard + F1/F1a/F1b/F1c/F2；"F-Chrome" 是富士**后续紧凑机型**（EXR 时代小型机）的胶片模拟命名，不属于 S5 Pro。

### 1.2 作用对象：影响机身 JPEG 的哪些参数

- **A（直接引文）** 评测第 14 页解释 Tone 调整的本质：*"Adjusting the tone alters the shape of the 'S curve' (gamma curve) used to map the linear image data captured by the sensor into the correct gamma"* —— 色调=把传感器线性数据映射到输出 gamma 的 **S 形色调曲线**，该曲线存在于处理管线（机身 JPEG 引擎/转换器），不是存储在 RAW 里的查表数据。
- **A（标签枚举）** ExifTool FujiFilm 标签页：富士 makernote 0x1001 Sharpness / 0x1003 Saturation / 0x1004 Contrast 的取值 **0x8000 = "Film Simulation"** —— 即胶片模拟激活时，这三个 EXIF 参数由模式整体接管，机身 JPEG 的色调曲线、饱和度、锐度同时被模式决定。
- **A（标签枚举）** 0x1401 FilmMode 枚举（ExifTool）：0x0=F0/Standard (Provia)、0x100=F1/Studio Portrait、0x110=F1a/Studio Portrait Enhanced Saturation、0x120=F1b/Studio Portrait Smooth Skin Tone (Astia)、0x130=F1c/Studio Portrait Increased Sharpness、0x200=F2/Fujichrome (Velvia)；另有 0x300=F3/Studio Portrait Ex、0x400=F4/Velvia、0x500/0x501=Pro Neg. Std/Hi（S5 Pro 之后机型及官方转换器输出所用）。

### 1.3 RAF 是否记录拍摄时的模式选择

- **A（源码）** LibRaw `parse_makernote`（`src/metadata/fuji.cpp:1071-1072`）：`case 0x1401: imFuji.FilmMode = get2();` —— 富士 makernote 中的胶片模式被读入 `makernotes` 元数据（初值 0xffff，`src/utils/init_close_utils.cpp:203`）。该 makernote 位于 RAF 内嵌 JPEG 的 EXIF 中。
- **A（第三方观察）** Radozhiva（radojuva.com，2021-06）用 Jeffrey's Metadata Viewer 直接读取 S5 Pro RAF 的 EXIF：F2 样片 EXIF 显示 D-RANGE='STANDARD'；F1a/F1b/F1c 样片使用 WIDE D-RANGE（比例未知）；机身菜单上 D-RANGE 字段对胶片模式显示"—"，具体值仅第三方工具可读。
- **B 推断**：radojuva 猜测 F1a/F1b/F1c 的 WIDE 即 400%（W2）——作者自己标注为推测，C 级孤证；但"模式选择与 D-RANGE 关联被写进 EXIF/makernote"本身为 A。

## 二、Q2：官方转换器能否对 RAF 后期更改胶片模式

### 2.1 已验证：HS-V3 / Hyper Utility 可后期选择胶片模拟

- **A（直接引文）** dpreview 评测第 13 页：*"Fujifilm's Hyper-Utility raw developer also offers film simulation presets, and although they are not exactly the same as those available in camera (why? it makes no sense!) they are similar."* 同页给出由 HS-V3 "CCD-RAW to TIFF" 功能直接产出的影棚闪灯人像样张，预设名为：**Standard · Pro Negative · F3a · F3b · F3c · Fujichrome**。
- **A（直接引文）** dpreview 论坛帖 3526066（2013-08-01）：楼主对**同一 RAF** 在 Hyper Utility 3 中分别以 PRO NEGATIVE / FILM SIMULATION F3a / F3b / F3c / Fujichrome 转换对比 —— 证明 HU3 显影时胶片模拟**可自由选择、可后期更改**（对已拍 RAF 而言）。
- **A（次级佐证）** perfefilm 博客（2021-12）：S5 Pro 的 Pro Negative/F3b/F3c/FujiChrome 等输出"必须用桌面软件 Hyper-Utility v3 转换"。
- **A（官方手册 TOC）** S5 Pro 说明书（dl.fujifilm-x.com `finepix_s5pro_manual_01.pdf`）目录：FILM SIMULATION p.111、D-RANGE p.112 等；正文指向随机/选购 **Hyper-Utility HS-V3** 软件。

### 2.2 未证实与推断（分层表述）

- **C 未证实**：HU3 的 Pro Negative↔F1、F3a↔F1a、F3b↔F1b、F3c↔F1c、Fujichrome↔F2 一一对应 —— 论坛帖内仅有个别用户猜测，无定论；dpreview 官方评测明确说"not exactly the same"。故只能断言"HU3 提供独立的胶片模拟预设集"，不能断言"等于机身档位"。
- **B 推断**：EX 3.0（SilkyPIX 系 RAW converter）不覆盖 S5 Pro；S5 Pro 时代的官方 RAW 显影工具是 HS-V3（说明书指向）。未做 EX 3.0 支持列表专项验证。
- **B 推断**：ExifTool 枚举中 0x300=F3、0x400=F4、0x500=Pro Neg. 等值对应 S5 Pro 之后机型（如 S100FS/S200EXR）及 HU3 输出文件。

### 2.3 空结果记录（C）

- **HS-V3 官方手册详文**：web_search（"HS-V3" manual film simulation F3a/F3b/Pro Negative）**0 命中**。
- **2007 年 dpreview 论坛帖 2054199**：直抓被反爬拦截，Wayback 无存档 —— 未取得。
- **说明书 PDF p.111 正文**：PDF 可解析出目录（FILM SIMULATION p.111 等），但正文文本截断于前部，p.111 原文未取得；以评测第 13 页的逐条转述（"According to the manual…"）作为手册内容的替代证据。

## 三、Q3：LibRaw `color.curve` 对富士 RAF 的填充机制

考察对象：本地解压的 **LibRaw 0.21.5** 源码（含 dcraw 9.28 副本），全部结论可直接复核。

### 3.1 初始化：恒等曲线

- **A（源码）** `src/metadata/identify.cpp:484-485`：
  ```c
  for (i = 0; i < 0x10000; i++)
    curve[i] = i;
  ```
  `src/utils/utils_dcraw.cpp:98-99` 同样初始化。即：**任何文件若不显式提供曲线表，`color.curve` 恒等**。

### 3.2 RAF 解析（parse_fuji）不产生曲线、不产生渲染用模式

- **A（源码）** `src/metadata/fuji.cpp` `parse_fuji()`（约 :1160 起）读取的 FujiIFD 标签仅有：尺寸/裁切/布局、白平衡（0x2ff0、0x2000–0x2410、0x2f00）、黑位（0x4000）、曝光补偿（0x9200/0x9650/0x9651）、RAFData（0xc000；dcraw.c:6722 从中读取尺寸表）。**无任何色调曲线表、无胶片模式标签**。
- **A（源码）** 胶片模式的唯一入口是内嵌 JPEG 的 makernote：`fuji.cpp:1071-1072` `case 0x1401: imFuji.FilmMode = get2();`，结果只存进 `imgdata.makernotes.fuji.FilmMode` 供元数据查询，**渲染管线不读取**（全源码仅写入与初始化两处）。
- **A（源码）** dcraw 9.28 的 `parse_fuji`（`dcraw/dcraw.c:6722`）与 RAF 头分支（:8701 附近）同样无曲线赋值。

### 3.3 全源码 `color.curve` 写入点普查（均非富士分支）

| 写入点 | 归属 |
|--------|------|
| `src/utils/open.cpp` ~1040-1055 多项式曲线 | **Nikon sRAW** 分支 |
| `src/metadata/identify.cpp:673` gamma_curve(0,12.25,1,1023) | Canon RMF（XPDS 头） |
| `src/metadata/identify.cpp:2964/2983` | Kodak 特殊机型 |
| `src/decoders/load_mfbacks.cpp:668` `curve[i]=i*i/3.969+0.5` | Phase One IIQ |
| `src/metadata/tiff.cpp:1991` gamma_curve(1/2.4,12.92,…) | Nikon YUV TIFF |
| `src/decoders/dng.cpp:227` 等 | DNG（sRGB 线性化/glue） |
| `mem_image.cpp:193`、`thumb_utils.cpp:186`、`write/file_write.cpp:179`、`postprocessing_utils_dcrdefs.cpp:53` 的 gamma_curve(O.gamm…) | **输出阶段用户 gamma 参数**，非文件数据 |

**富士分支无一命中** —— Q3 的核心答案：LibRaw 对富士 RAF 的 `color.curve` 只能是 3.1 的恒等默认值。

### 3.4 渲染路径与 S5 Pro 特性

- **A（源码）** dcraw `adobe_coeff` 表中 S5 Pro 仅有**固定色彩矩阵**（`dcraw/dcraw.c:7392-7393`：12300,-5110,-1304,-9117,17143,1998,-1947,2448,8100）。
- **A（源码）** 输出查表：`src/postprocessing/mem_image.cpp:224-242` 直接 `imgdata.color.curve[像素值]` 查表输出。恒等曲线 ⇒ 富士 RAF 在 LibRaw 中=线性原始数据 + 白平衡/黑位/固定矩阵，**无任何胶片模式影响**。
- **A（第三方引文）** Radozhiva：Capture One 完全不理解 Super CCD SR II 的 R 像素（只读 S 像素）；第三方引擎（ACR/LR）对 6MP/12MP 输出尺寸处理也不一致 —— 印证非官方引擎对 S5 Pro RAF 的还原不完整。

### 3.5 层级结论

- **A（源码已验证）**：S5 Pro 时代富士 RAF 中**没有** LibRaw/dcraw 可解析的内嵌色调曲线；`color.curve` 恒等；机身胶片模式仅以 makernote 元数据形式随 RAF 记录。
- **B（推断）**：胶片模式的色调曲线/色彩处理仅存在于（a）机身 JPEG 处理管线、（b）官方 HS-V3/Hyper Utility 闭源显影引擎。RAF 内未公开数据区（如 0xc000 RAFData 未解析部分）理论上可能藏有私有处理数据，但 LibRaw/dcraw 均未读取，且无公开文档。
